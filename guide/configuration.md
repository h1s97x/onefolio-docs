# 环境变量与系统设置

配置分两层：

| 层       | 位置                         | 变更生效                 | 适合放什么                                           |
| -------- | ---------------------------- | ------------------------ | ---------------------------------------------------- |
| 环境变量 | 部署目录 `.env`              | 重建容器                 | 密钥、数据库连接、端口、存储路径等启动期必需项       |
| 系统设置 | 应用内「系统设置」页（超管） | 保存即生效，**无需重启** | 智能体节点、报告类型、邮件、告警、数据保留、支持信息 |

::: tip 库配置优先
同一项在两处都能配时（如 SMTP），**库里有值的字段优先于环境变量**，逐字段回退。环境变量是「未在界面上配置时」的兜底。
:::

## 1. 启动期必填（缺失即拒绝启动）

| 变量                        | 说明                                                                                                        |
| --------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `SUPABASE_URL`              | 私有化部署填 `http://gateway:8080`（compose 内网网关），由 `gen-keys.sh` 写入模板                           |
| `SUPABASE_SERVICE_ROLE_KEY` | `role=service_role` 的长期 JWT，由 `gen-keys.sh` 生成。应用只用这一把服务端密钥（RLS 已对 `anon` 默认拒绝） |
| `AUTH_SECRET`               | 会话签名密钥，`openssl rand -base64 32`。NextAuth 要求非空                                                  |

应用启动时会校验这三项（`src/instrumentation.ts`），缺失直接 fail-fast，不会带病启动。

## 2. 私有化编排（docker compose）

| 变量                       | 默认 / 取值            | 说明                                                                                                                |
| -------------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `ONEFOLIO_IMAGE`           | 由交付方提供           | 应用镜像坐标（`<镜像仓库>/onefolio:<version>`）；离线包场景由 `load-image.sh` 导入本地 tag                          |
| `APP_PORT`                 | `5000`                 | 应用对外端口（容器内固定 5000）                                                                                     |
| `POSTGRES_DB`              | `onefolio`             | 数据库名                                                                                                            |
| `POSTGRES_USER`            | `postgres`             | 数据库超级用户                                                                                                      |
| `POSTGRES_PASSWORD`        | 必填，无默认           | 数据库口令；PostgREST 的 `authenticator` 角色复用它                                                                 |
| `PGRST_JWT_SECRET`         | 必填，无默认           | PostgREST 校验 JWT 的 HS256 密钥                                                                                    |
| `BOOTSTRAP_ADMIN_PASSWORD` | 必填，**≥ 12 位**      | 首个 `super_admin` 的初始口令，仅首次启动播种时使用；设 `SKIP_BOOTSTRAP_ADMIN=1` 时可不填（改用 `/setup` 自助创建） |
| `SKIP_BOOTSTRAP_ADMIN`     | `0`                    | `=1` 跳过初始化播种，改为部署后访问 `/setup` 创建首个管理员                                                         |
| `SUPABASE_ANON_KEY`        | `gen-keys.sh` 副产物   | **应用已不再读取**；保留仅为历史兼容与人工调试 PostgREST                                                            |
| `STORAGE_DIR`              | 容器内 `/data/storage` | 生成文件的落盘目录，必须位于持久卷                                                                                  |
| `EXPORT_DIR`               | 容器内 `/data/exports` | 导出包（zip）落盘目录，必须位于持久卷                                                                               |

::: danger 密钥必须同源配对
`PGRST_JWT_SECRET`、`SUPABASE_SERVICE_ROLE_KEY`、`SUPABASE_ANON_KEY` 三者由 `gen-keys.sh` **一次生成**。重新生成任意一项时，必须同时替换三处（数据库 PostgREST 配置 + 应用 `.env`），否则表现为接口 401。

轮换 `AUTH_SECRET` 或 `PGRST_JWT_SECRET` 都会让**所有在线会话失效**，请在维护窗口执行。
:::

## 3. 应用行为

| 变量                      | 默认               | 说明                                                                                                           |
| ------------------------- | ------------------ | -------------------------------------------------------------------------------------------------------------- |
| `APP_URL`                 | 取请求 origin      | 应用外部地址。**仅用于 SSO 回调缺省值**，切勿填容器内地址                                                      |
| `SMTP_HOST`               | 空                 | 邮件服务器；也可在「系统设置 → 邮件」配置（库配置优先）                                                        |
| `SMTP_PORT`               | `587`              | 端口                                                                                                           |
| `SMTP_USER`               | 空                 | 账号                                                                                                           |
| `SMTP_PASS`               | 空                 | 口令。落库时用 `SETTINGS_ENCRYPTION_KEY`（缺省回退 `AUTH_SECRET`）加密                                         |
| `SMTP_FROM`               | 空                 | 发件人                                                                                                         |
| `ALERT_EMAIL`             | 空                 | 任务失败告警收件人，**仅从环境变量读取**；不配则不发送告警                                                     |
| `SETTINGS_ENCRYPTION_KEY` | 回退 `AUTH_SECRET` | 加密落库敏感设置项（当前为 SMTP 口令）。轮换后需在设置页重新填写一次邮件口令                                   |
| `SETUP_TOKEN`             | 空（不要求）       | 首次初始化入口 `/setup` 的一次性令牌。配置后创建首个管理员必须带上它 —— 内网交付建议设置，避免被他人抢先初始化 |

## 4. 首次初始化（首个管理员怎么来）

两种方式**二选一**：

| 方式                 | 配置                                  | 说明                                                                     |
| -------------------- | ------------------------------------- | ------------------------------------------------------------------------ |
| 初始化时播种（默认） | `BOOTSTRAP_ADMIN_PASSWORD`（≥ 12 位） | 首次启动时由初始化脚本创建 `admin`；缺失或过短会导致数据库初始化直接中断 |
| 部署后自助创建       | `SKIP_BOOTSTRAP_ADMIN=1`              | 跳过播种，部署完成后访问 `http://<部署主机>:5000/setup` 创建             |

`/setup` 的三道闸：

1. 仅当库中**没有任何超级管理员**时可用，创建成功即永久关闭（再次调用返回「系统已初始化」）；
2. 配置了 `SETUP_TOKEN` 时，必须提供正确令牌；
3. 口令沿用全站复杂度策略（至少 8 位，含大小写字母、数字、特殊字符）。

::: danger 这是提权入口
`/setup` 不需要登录（此时系统里还没有账号可登录）。请确认初始化窗口期内的访问环境可信，
并在初始化完成后验证该入口已关闭（页面会显示「系统已初始化」）。内网交付建议配置 `SETUP_TOKEN`。
:::

## 5. 智能体（Agent）接入

::: warning 多节点请在界面上配置
在「系统设置 → 节点」配置了**至少一个启用节点**后，下面的 `AGENT_*` 环境变量全部失效（被库配置覆盖）。

`AGENT_*` 只用于「一个节点都没有」的单节点兜底形态。
:::

| 变量                       | 默认                                    | 说明                                                                         |
| -------------------------- | --------------------------------------- | ---------------------------------------------------------------------------- |
| `AGENT_API_URL`            | 空                                      | 单节点兜底：生成任务的智能体接口地址。缺失且无节点时任务直接失败并提示未配置 |
| `AGENT_API_TOKEN`          | 空                                      | 作为 `Authorization: Bearer` 发送                                            |
| `AGENT_PROJECT_ID`         | 空                                      | 项目 / 应用 ID                                                               |
| `AGENT_TIMEOUT`            | `600`                                   | 单次调用超时（秒）                                                           |
| `AGENT_REQUEST_METHOD`     | `POST`                                  | 调用方法                                                                     |
| `AGENT_EXTRA_HEADERS`      | 空                                      | 额外请求头（如 `X-Env: prod`）                                               |
| `AGENT_ALLOWED_DOMAINS`    | 空（不限制域名）                        | 允许智能体返回的文件下载域名白名单，逗号分隔。内网/回环地址始终拦截          |
| `AGENT_ALLOWED_EXTENSIONS` | `docx,pdf,doc,xlsx,xls,pptx,ppt,txt,md` | 允许的文件扩展名白名单                                                       |

## 6. 门户单点登录（可选）

三项齐备才启用；未启用时访问 SSO 入口会提示「单点登录未启用」。

| 变量                   | 说明                                                                          |
| ---------------------- | ----------------------------------------------------------------------------- |
| `OAUTH2_AUTH_HOST`     | 统一认证地址，不要带结尾斜杠                                                  |
| `OAUTH2_CLIENT_ID`     | 客户端 ID                                                                     |
| `OAUTH2_CLIENT_SECRET` | 客户端密钥                                                                    |
| `OAUTH2_REDIRECT_URI`  | 回调地址，必须与门户侧登记值完全一致；缺省 `${APP_URL}/api/auth/sso/callback` |

::: danger 三条红线

1. 门户地址与密钥**只允许**通过运行时环境变量注入，禁止写入代码、文档或提交到仓库。
2. 回调地址不可使用容器内地址（如 `0.0.0.0:5000`），请显式配置或正确设置 `APP_URL`。
3. 门户接口异常只回传固定文案与错误码，工号等身份信息不会出现在 URL 或日志中。
   :::

## 7. 脚本级开关（交付/升级时用）

| 变量                   | 说明                                                                                |
| ---------------------- | ----------------------------------------------------------------------------------- |
| `SKIP_SCHEMA_CHECK=1`  | 跳过 `01_schema.sql` 的 `CREATE TABLE` 校验。**仅用于升级部署**（目标库已有表结构） |
| `BUNDLE_BASE_IMAGES=1` | 制包时把 Postgres / PostgREST / nginx / alpine 基础镜像一并导出（完全隔离内网必备） |
| `DEPLOY_RUN_PORT`      | 常驻启动脚本 `scripts/start.sh` 监听端口，默认 `5000`                               |

## 8. 应用内「系统设置」

保存后立即生效（后端刷新缓存），无需重启容器。

| 页签 | 配什么                                         | 要点                                                                                                       |
| ---- | ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 节点 | 智能体节点池：地址、令牌、并行任务数、服务类型 | 每个节点的「服务类型」勾选它承接哪些报告产品；一个都不勾表示「未声明」，仅在某类型没有任何已声明节点时兜底 |
| 类型 | 报告类型（产品）注册表                         | 标识（code）保存后不可修改——落库字段与节点归属都用它；新增产品：先加类型，再去节点页勾选                   |
| 邮件 | SMTP 服务器与收件人                            | 环境变量为兜底，库里有值优先；含「发送测试邮件」验证链路                                                   |
| 告警 | 任务失败通知、最大重试次数                     | 失败告警走邮件，收件人来自 `ALERT_EMAIL` 或此处配置                                                        |
| 数据 | 日志保留天数                                   | 到期自动清理，附带清理结果（删除条数、是否截断）                                                           |
| 支持 | 维护人联系方式                                 | 全站错误提示与页脚的联系方式，一处配置多处生效                                                             |

::: tip 报告类型与节点必须成对配置
新增一个报告产品有且只有两步：**「类型」页加一条 → 「节点」页给对应节点勾上它**。

只加类型不勾节点，用户在选择器里看不到该产品（没有节点承接就不该给用户选，点了必然失败）。系统**不会**把某类型的任务派给服务其它类型的节点——用行研节点跑访前会产出一份「看起来正常但产品不对」的文件，比直接失败更难发现。
:::
