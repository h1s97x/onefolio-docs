# 故障排查

按「现象 → 原因 → 处理」组织。**先看日志**：`docker compose logs --tail=200 app` / `docker compose logs db | head -50`。

排障前可以先跑一次交付包自带的诊断脚本（只读，输出 CPU/OS/Docker/资源/端口/包完整性/镜像/服务状态汇总，便于直接贴给维护方）：

```bash
bash scripts/diagnose.sh
```

## 部署与启动

| 现象                                           | 原因                                                                        | 处理                                                                                                            |
| ---------------------------------------------- | --------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 启动即报「缺少必需环境变量」                   | `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` / `AUTH_SECRET` 未注入         | 补齐 `.env` 后 `docker compose up -d`                                                                           |
| `relation "users" does not exist`              | 数据库初始化中断过（如 initdb 脚本顺序错误）                                | 看 `docker compose logs db` 的首个报错；修正后 `docker compose down -v` **清卷重来**                            |
| db 容器反复重启、库里没有表                    | initdb 某脚本报错（`ON_ERROR_STOP=1` 中断）；已初始化的数据目录**不会**重跑 | 修正脚本后删卷重建                                                                                              |
| 首次部署后没有 `admin` 账号                    | `BOOTSTRAP_ADMIN_PASSWORD` 缺失或不足 12 位，播种脚本 fail-fast             | 检查 initdb 日志；补好口令后清卷重来                                                                            |
| `image not found` / `pull access denied`       | 离线包只含应用镜像，缺基础镜像                                              | `docker pull --platform linux/<arch> postgres:16-alpine postgrest/postgrest:v13.0.4 nginx:1.27-alpine alpine:3` |
| arm64 / 信创机器拉不到可用镜像                 | 平台不匹配                                                                  | 显式 `--platform linux/arm64`，或用 `BUNDLE_BASE_IMAGES=1` 打全量离线包                                         |
| `deploy.sh` 报 01_schema.sql 不含 CREATE TABLE | 建表脚本为空（占位文件）                                                    | 补全建表结构；若目标库已有表结构（升级部署）用 `SKIP_SCHEMA_CHECK=1` 跳过                                       |
| 应用启动 120 秒仍未 healthy                    | 依赖没起来或配置错                                                          | `docker compose ps` 看各容器状态，再看 app 日志首屏报错                                                         |

## 认证与会话

| 现象                                      | 原因                                  | 处理                                                                                              |
| ----------------------------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 接口 401                                  | 应用 JWT 与 `PGRST_JWT_SECRET` 不匹配 | 重新执行 `gen-keys.sh`，**同时更新三处**（PostgREST 密钥 + 应用 `.env` 的两把 key）               |
| 重启后所有人被强制登出                    | `AUTH_SECRET` 变了（或未挂载/未固定） | 固定 `AUTH_SECRET` 不要每次随机生成                                                               |
| 登录报「用户名或密码错误」但确认口令正确  | 账号被停用，或不在数据范围内          | 用超管在「用户管理」确认账号状态                                                                  |
| SSO 登录失败，跳回 `/login?error=sso_xxx` | 门户侧配置或回调地址不一致            | 对照[配置参考的 SSO 三项](./configuration#_6-门户单点登录-可选)与门户登记值；回调地址必须完全一致 |
| 部分用户 SSO 成功、部分失败               | 工号在本地用户表中不存在或未启用      | 先在「用户管理」建好账号（SSO 按工号匹配）                                                        |

## 任务与生成

| 现象                                       | 原因                                           | 处理                                                    |
| ------------------------------------------ | ---------------------------------------------- | ------------------------------------------------------- |
| 提交任务提示「智能体未配置」               | 没有启用节点，且 `AGENT_API_URL` 为空          | 在「系统设置 → 节点」配置节点，或补 `AGENT_API_URL`     |
| 提示「该报告类型暂不可用」                 | 该类型没有任何节点承接（系统不会跨类型回落）   | 在「系统设置 → 节点」给节点勾上该报告类型               |
| 提示系统繁忙（429）                        | 该报告类型并发闸已满                           | 看节点运行状态：是 Agent 变慢还是节点被隔离             |
| 同一公司名提交返回冲突                     | 同用户 + 同公司名 + 同报告类型已有进行中任务   | 等它结束，或取消后重试                                  |
| 任务莫名其妙「已完成」但没有真正调用智能体 | 命中当日缓存快路径（同公司名当日已有完成记录） | 属预期，用于省成本；需要强制重跑请用「重新生成」        |
| 任务失败率突然升高                         | Agent 侧不稳定 / 节点被隔离 / 网络策略变更     | 看节点状态接口的连续失败与隔离冷却；确认 Agent 地址可达 |

## 批量生成

| 现象                           | 原因                                                 | 处理                                                                                         |
| ------------------------------ | ---------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 批次长时间停在「生成中」       | 调度循环所在进程被回收（Serverless 形态）            | 见[运维总览第 4 节](./operations#_4-批量卡住怎么处理)；Serverless 需配每分钟的 tick 定时任务 |
| 大量任务被标记「任务执行中断」 | 失联任务回收机制误杀（进程被回收或 Agent 调用挂住）  | 先解决长驻进程；再评估提高失联阈值                                                           |
| 批次没跑完就显示「已完成」     | 分母只统计实际创建的任务（已生成过的被跳过的不计入） | 属预期；要看全量请用「全部重跑」                                                             |
| 批量导出 zip 为空              | 该地市/批次没有已完成任务                            | 确认完成数 > 0                                                                               |
| 「续跑」后失败任务没重跑       | 续跑只推进 `pending`；失败任务需先重置               | 用「重新启动」会把失败重置为待处理                                                           |

## 文件与存储

| 现象                            | 原因                       | 处理                                                                                        |
| ------------------------------- | -------------------------- | ------------------------------------------------------------------------------------------- |
| 重启/重建容器后历史报告下载不到 | `/data` 未挂持久卷         | 挂上 `onefolio-data` 卷；历史上已丢的文件无法找回                                           |
| 下载文件名乱码或截断            | 反向代理对文件名头处理不当 | 确认代理放行 `Content-Disposition`，且未做 URL 规范化改写                                   |
| 预览大文件失败                  | 代理缓冲/超时              | 关闭响应缓冲（`proxy_buffering off`）并放宽 `client_max_body_size`；生成文件通常较大        |
| 微信内打不开下载                | 微信内置浏览器限制         | 引导用户在外部浏览器打开，页面本身已有提示                                                  |
| 多副本时部分文件读不到          | 本地磁盘存储 + 进程内状态  | **不要扩多副本**；确需扩容请用 NFS 共享同一 `STORAGE_DIR`，并参考[部署边界](./architecture) |

## 性能与容量

| 现象             | 建议                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------- |
| 并发上不去       | 上限 = 承接该类型的节点 `concurrency` 之和；先加节点或调大并行数，并确认 Agent 侧能扛 |
| 批量太慢         | 单批约 6 任务/分钟。调大批次并发（建议 ≤ 5，单节点场景）或缩短 tick 间隔，两处都要改  |
| 数据库体积增长快 | 检查「系统设置 → 数据」的日志保留天数，过长会持续占用 `pgdata` 卷                     |
| 磁盘告警         | `/data` 卷存生成文件与导出包，需按业务量规划容量并纳入监控                            |
